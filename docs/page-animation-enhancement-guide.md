# Smart Home 各页面动画优化、美化与新增建议

## 1. 目标与原则

本文档覆盖 `smarthome-web` 当前 7 个路由页面，给出可实施的动画优化、美化和新增建议。方案沿用现有 Vue 3、GSAP、Morphicons、Motion Token 与 MotionMode，不改变业务接口。

动画只用于表达页面切换、空间关系、内容增删和业务状态。简单 hover、active、focus 和颜色变化继续使用 CSS；多步骤状态使用 GSAP Timeline；列表重排使用 Flip；图标变化使用 Morphicons。

全局约束：

- 路由入场只保留一层。当前 `App.vue` 的路由 `slide-up` 与页面 `.page-enter` 不应叠加。
- GSAP 在 `onMounted` 后通过组件根节点作用域创建，卸载时 `context.revert()`。
- full 模式播放完整动画；reduced 只保留淡入和颜色反馈；off/lite 直接呈现终态。
- 优先使用 `autoAlpha`、`x/y`、`scale`；避免持续修改 width、height、margin、top、left。
- 多元素 stagger 控制总时长，避免元素越多动画越慢。
- 动画不能延迟保存、删除、执行和路由跳转等业务操作。

建议节奏：微交互 140ms，状态反馈 180–220ms，面板切换 220–280ms，页面或卡片入场 280–360ms。

## 2. 全屋总览 `/overview`

### 当前重点

页面包含统计卡、房间分布、设备状态、活动记录、快捷操作和详情对话框，已使用 `useCardGridEnter` 处理统计与房间网格入场。

### 美化建议

- 统一统计卡高度，数字、单位和趋势基线对齐。
- 房间卡重点展示在线数、环境状态和当前场景，减少同层级装饰色。
- 快捷操作区区分主操作与次操作，避免所有按钮都使用高饱和背景。
- 刷新使用局部遮罩，不让整页闪白或重新入场。

### 建议增加

- 统计值变化沿用数字补间，趋势图标通过 Morphicons 切换，不缩放整张卡。
- 房间在线数、温湿度变化时，仅对变化字段做一次 160ms 颜色强调。
- 刷新按钮由 refresh Morph 到 check，成功后一次轻微 scale 再恢复。
- 新增房间卡通过 Flip 从网格末尾进入，并短暂显示主色边框。
- 房间卡打开详情时仅保持图标和标题的视觉连续，弹窗主体使用公共模态 Timeline。

### 应修改或删除

- 删除页面根节点 `.page-enter`，避免与路由过渡叠加。
- 卡片 stagger 只在首次加载成功时执行，刷新和返回页面不重播。
- 统计卡与房间卡不要同时大批量 stagger，整体入场不超过 420ms。
- loading 只作用于触发按钮或局部区域。

## 3. 房间控制 `/rooms`

### 当前重点

页面包含统计、筛选、房间网格、设备控制面板和右侧助手。目前同时存在 GSAP 网格入场、TransitionGroup、统计淡入和侧栏折叠。

### 美化建议

- 选中房间使用稳定边框和背景，不使用持续 pulse。
- 设备控制按灯光、空调、窗帘等类别分组，统一层级、间距和圆角。
- 环境趋势保持低对比背景，动画只强调最新采样点。
- 助手侧栏与当前房间使用相同主题色，建立关联。

### 建议增加

- 切换房间时，选中卡背景过渡 180ms；控制面板使用 `autoAlpha + x: 8` 交叉切换。
- 房间筛选、展开、新增和删除使用事务 Flip 保持位置连续。
- 设备开关通过 Morphicons 与状态色表达 pending/success/error。
- 温湿度和空气质量使用数字补间；趋势图只绘制新增段。
- 助手侧栏使用真正可逆 Timeline，连续点击从当前进度反向。

### 应修改或删除

- TransitionGroup move 与 Flip 不得同时控制同一批房间卡片。
- 删除选中态无限 `pulse-dot`，改为静态状态点或一次性反馈。
- `.panel-enter` 只用于首次展示，切换房间使用短交叉淡入。
- 侧栏宽度只能由 CSS 或 GSAP 中的一方控制。

## 4. 设备管理 `/devices`

### 当前重点

页面包含平台接入、统计、筛选、列表/网格、批量操作、详情侧栏、同步和日志，当前存在多个 spinner、日志入场和布局型不确定进度。

### 美化建议

- 在线、离线、告警统一使用语义色，平台品牌色不覆盖健康状态。
- 列表和网格共用选中样式、状态标签和操作按钮层级。
- 批量操作栏贴近选中内容，使用轻量浮层而非高饱和整条背景。
- 同步过程按平台、阶段、结果组织，避免多个图标同时旋转。

### 建议增加

- 列表/网格切换使用 Flip，保持设备项位置连续。
- 设备状态点、标签和操作图标同步切换；失败时恢复原状态。
- 批量操作栏以 `y: 8 + autoAlpha` 进入，选中数量使用数字补间。
- 同步 Timeline 依次表达连接平台、读取设备、更新状态、完成，步骤由真实任务状态驱动。
- 新日志轻微进入，历史日志不重播；失败日志一次性强调边框。

### 应修改或删除

- 将批量删除进度从 width/margin 动画改为固定指示条的 `xPercent + scaleX`。
- 合并重复 spinner，单个操作只保留一个主要 loading 指示。
- 删除设备页面根节点 `.page-enter`。
- 长列表不逐行 stagger，只动画新增、删除、变化和可见项目。

## 5. 场景模式 `/scenes`

### 当前重点

页面包含统计、工具栏、场景网格、执行流程、详情、风险确认、模板、日志和排序。场景执行适合 Timeline，但目前仍有 spinner 和 icon pulse。

### 美化建议

- 场景卡突出图标、名称、设备数量和风险等级。
- 执行中使用进度描边或状态条，不让整卡持续呼吸。
- 高风险确认依靠稳定警告色和清晰文案，不使用大幅摇晃。
- 流程节点使用统一尺寸和连接线，成功、失败、等待明确区分。

### 建议增加

- 场景执行 Timeline 按真实事件更新 pending、running、success、error。
- 步骤成功后连接线用 `scaleX` 从弱色变为成功色，无需 DrawSVG。
- 启停状态文案、颜色和图标同步过渡；失败时恢复原值。
- 排序对话框使用 Flip；真正支持拖拽时再按需引入 Draggable。
- 模板创建成功后，新场景卡通过 Flip 加入网格并突出来源标签一次。

### 应修改或删除

- 删除非执行状态的无限 `icon-pulse`。
- 完成或失败后立即停止 spinner 和呼吸动画。
- 场景网格只在首次加载时入场，执行单个场景不重播全网格。
- 高风险确认只播放一次短促强调，不 repeat、不 yoyo。

## 6. 自动化中心 `/automations`

### 当前重点

页面包含统计、筛选、自动化卡片、规则流程、执行记录和批量对话框，已使用卡片 GSAP 入场，但仍有多个 spinner 和 icon pulse。

### 美化建议

- 卡片按触发器、条件、动作展示摘要，减少无含义色块。
- 启用状态与运行状态使用不同视觉语义。
- 选中规则和流程面板使用相同强调色。
- 执行记录统一成功、失败、执行中图标和时间排版。

### 建议增加

- 筛选与展开全部使用事务 Flip，现有卡片不重新 stagger。
- 运行按钮 Morph 为 loading，完成后 Morph 为 check/warning。
- 选择规则时，标题和步骤列表使用 180–220ms 交叉淡入。
- 复制规则后，新副本从原卡片附近通过 Flip 出现并高亮名称一次。
- 批量启用只动画实际变化的可见卡片，统计数字同步补间。

### 应修改或删除

- 删除非运行状态的 `icon-pulse`。
- 合并多处 900ms spinner 为公共 loading 动画。
- 首次卡片 stagger 与路由入场总时长不超过 420ms。
- 动画只消费请求状态，不延迟保存或运行请求。

## 7. 智能对话 `/`

### 当前重点

页面包含聊天窗口、消息列表、输入区、Agent 状态、审批卡和右侧上下文卡。目前存在消息 Flip、自动滚动、思考动画和右栏 pulse。

### 美化建议

- 对话区域保持稳定，消息动画轻于其他控制台卡片。
- 用户和助手消息依靠排版、底色和头像区分，不大幅左右飞入。
- Agent 工具调用、审批和最终答案建立清晰层级，避免多个状态同时闪动。
- 右侧卡片只在数据变化时局部反馈，不持续呼吸。

### 建议增加

- 用户消息从 `y: 6` 进入，助手消息从 `y: 8 + autoAlpha` 进入。
- 消息删除、重新生成使用“捕获旧布局—更新 Store—nextTick—Flip”。
- 发送图标 Morph 到停止图标，结束后恢复，按钮尺寸保持不变。
- Agent Timeline 串联思考、工具执行、等待确认、完成；进入审批时停止思考循环。
- 只有用户接近底部时才自动跟随流式内容，向上阅读后不抢夺滚动位置。
- 设备、能耗、安全卡只对发生变化的字段强调一次。

### 应修改或删除

- 修正当前消息数量变化后才捕获 Flip 的时机。
- 删除无条件无限 `rail-dot-pulse`，只在任务进行中显示。
- 流式 token 不逐 token 创建 Tween，光标继续使用轻量 CSS 闪烁。
- 删除聊天页面自身 `.page-enter`。
- 批量加载历史消息不逐条入场，并保持滚动锚点。

## 8. 设置中心 `/settings`

### 当前重点

页面包含目录、账户家庭、成员、外观、通知、智能助手、模型服务、安全和备份，使用 IntersectionObserver 同步目录，并有状态淡入、保存 spinner 和大量弹窗。

### 美化建议

- 设置卡片以信息密度和对齐为主，避免大幅位移和持续装饰动画。
- 同一行卡片的顶部摘要、入口按钮和内容基线保持一致。
- 保存、未保存和错误状态统一在底部操作栏表达。
- 模型服务、账户摘要和成员摘要使用一致的紧凑信息卡语言。

### 建议增加

- 点击目录后使用原生平滑滚动，活动背景和指示条过渡 160ms。
- 保存按钮图标 Morph 为 loading/check/warning；成功反馈只播放一次。
- 错误字段边框和辅助文字一次淡入，自动定位首个错误字段，不持续 shake。
- 模型连接状态在未检测、检测中、正常、失败间通过图标和语义色过渡。
- 家庭切换只更新相关卡片；成员新增、删除和角色变化使用局部 Flip。
- 主题和字号即时预览，主题切换只过渡颜色，不让整页 fade 或 scale。

### 应修改或删除

- 设置页不使用页面级 `.page-enter`，卡片滚动进入视口也不反复动画。
- spinner 只在保存按钮内部运行，不让多个设置卡片同时 loading。
- 删除与全局 MotionMode 完全重复的局部 reduced-motion 规则。
- 各设置弹窗统一使用 `BaseSmartModal` Timeline。
- 账户摘要等静态信息不增加 hover 上浮。

## 9. 全局导航与壳层

### 建议增加

- 桌面侧栏 active 指示条使用 160–220ms 的 y/height 过渡。
- 移动端遮罩淡入、抽屉 `xPercent` 滑入，关闭时可逆。
- 最近会话新增、删除和排序使用 Flip，当前会话保持稳定高亮。
- 侧栏折叠使用单条 paused Timeline，通过 play/reverse 响应连续点击。

### 应修改或删除

- 路由过渡和页面根入场只保留一个动画所有者。
- `.app-shell` 网格列变化与侧栏 width 不同时由 CSS 和 GSAP 控制。
- 不引入全局 ScrollSmoother 或滚动劫持。
- 品牌标识保持静态，不增加持续旋转、漂浮或 glow。

## 10. 对话框统一规范

- 遮罩 180–220ms 淡入，面板 220–280ms `autoAlpha + y: 12 + scale: 0.98`。
- 快速关闭先 kill 旧 Timeline，Vue `done()` 只调用一次。
- 入场完成后聚焦，退场完成后恢复触发元素焦点。
- 表单最多对 3–5 个结构区块 stagger，不逐字段延迟。
- 危险操作依靠颜色、文案和确认结构，不持续摇晃。
- reduced/off/lite 直接呈现终态，但焦点和 modal stack 行为不变。

## 11. 实施优先级

### P0：正确性与性能

1. 去掉路由和页面双重入场。
2. 修正聊天、房间、设备列表的 Flip 事务时机。
3. 统一可逆侧栏 Timeline。
4. 修正模态快速开关和焦点时序。
5. 将 width/margin 型进度改为 transform。

### P1：业务反馈

1. 统一设备、场景、自动化的 pending/success/error 动画。
2. 全屋和设置页数字、状态使用局部反馈。
3. 房间、场景和自动化卡片增删重排使用 Flip。
4. 骨架到真实内容增加短交叉淡入。

### P2：按需求扩展

- 长报告或超长列表出现后再评估 ScrollTrigger。
- 真正需要拖拽排序时再引入 Draggable。
- 需要可取消程序化滚动时再引入 ScrollToPlugin。
- 不使用 MorphSVG 替代现有 Morphicons。

## 12. 页面验收矩阵

| 页面 | 核心验收场景 |
|------|--------------|
| 全屋总览 | 首次加载、刷新、房间新增、数字更新 |
| 房间控制 | 快速切换、筛选、展开、侧栏连续折叠 |
| 设备管理 | 列表/网格切换、批量选择、同步、日志新增 |
| 场景模式 | 执行、风险确认、失败重试、排序 |
| 自动化中心 | 筛选、运行、复制、批量启用、删除 |
| 智能对话 | 流式输出、停止、审批、历史加载、重新生成 |
| 设置中心 | 主题切换、保存失败、模型测试、成员变更 |

所有页面同时验证 full、reduced、off、lite，以及桌面、平板和移动端布局。

## 13. 完成定义

1. 每个动画都有明确的信息表达目的。
2. 路由、页面、列表和组件不存在重复动画所有权。
3. 主要动画使用 transform、opacity 和必要颜色，不产生持续 Layout 抖动。
4. 快速连续交互可以中断或反向，不出现状态错序。
5. 路由卸载后不存在活动 Tween、Timeline、Flip 或监听器。
6. reduced/off/lite 直接呈现稳定、可操作的终态。
7. 类型检查、构建、chunk 预算和页面交互回归全部通过。
