> **用「1B 小模型 + Jetson 边缘设备」跑起一个安全、可长期对话的智能家居智能体。**

### 2.2 技术创新点

> **模板要求**：通过相关技术对比调研，简单阐述项目的主要技术创新点。

- **📌 写作要点**：每个创新点都要有「**与现有方案的区别**」；结合「小模型 + 边缘设备」这个前提，说明**为什么这些技术点在边缘场景下更关键**。建议 4–5 个。
- **✍️ 建议内容**（本项目亮点 + 模型 / 设备结合）：
  1. **上下文压缩（边缘刚需）**：1B 小模型上下文窗口更短（如 8K–32K），压缩从「锦上添花」变成「能不能用长对话」的关键；切割点算法 + 双路径 token 估算 + 迭代式摘要 + 分支摘要，摘要回注模型——让边缘小模型也能「带着记忆」工作。
  2. **会话树形存储（轻量可审计）**：append-only 树 + 车道 + 操作记录，在存储 / 内存有限的边缘设备上实现可分支、可恢复、可审计的会话状态。
  3. **风险分级与人工审批（补偿小模型）**：小模型推理能力弱、易幻觉，用规则化风险分级 + 写操作强制人工确认，把安全兜底做在前面，适配门锁 / 安防等高风险家居操作；高风险与未知风险不可绕行，审批带有效期并支持主动取消，写操作全程可审计，同一会话并发互斥防止状态串线。
  4. **大模型驱动的场景编排**：自然语言 → 结构化自动化规则，替代表单式规则引擎。
  5. **轻量边缘部署**：1B 模型经 INT4/INT8 量化后仅需约 1–2GB 显存即可在 Jetson 上运行；项目模型接入层采用 OpenAI 兼容协议，vLLM / llama.cpp / Ollama 等本地服务可直接接入，几乎零改动落地边缘。

> **模板要求**：请阐述项目所需的数据如何采集、行业知识如何获取，是否有足够的算力、硬件支持保证项目顺利进行等可行性分析。

- **✍️ 建议内容**：
  - 数据采集：设备状态与执行结果由模拟器生成；工具参数结构自定义，规模可控。
  - 行业知识：设备类型与场景模式属公开常识，整理为风险策略库 + 系统提示词，无需大规模训练数据。
  - 算力硬件（核心论证）：
    - MiniCPM 1B 参数量约 1B，**INT4 量化后模型权重约 0.5–1GB**，加上推理时 KV cache，可在 Jetson 的 4–8GB 显存上运行；
    - Jetson 有 CUDA / TensorRT，可配 llama.cpp（CUDA 后端）或 TensorRT-LLM 做加速；
    - 生成速度（tokens/s）请**实测后填具体数值**（此处留占位，作为可行性证据）。

### 3.2 技术细节

> **模板要求**：请阐述项目相关技术细节，并结合可行性分析对核心技术进行论证及预期技术指标。

- **📌 写作要点**：全文核心，按「总体架构 → 模型部署 → 各核心模块 → 预期指标」展开；每个模块落到代码证据 + 论证，可配架构图、时序图。
- **✍️ 建议结构**：
  1. **总体架构**：前端（Vue 3 + SSE）→ 后端（FastAPI + LangGraph，运行于 Jetson）→ 本地模型服务（MiniCPM 1B）→ 存储（SQLite + 会话树 + 检查点）。
  2. **模型本地部署与推理优化**（新增，重点）：
     - 用 vLLM / llama.cpp server / Ollama / TensorRT-LLM 把 MiniCPM 暴露成 OpenAI 兼容接口；
     - 项目 `app/agents/providers/openai_compatible.py` 已支持 OpenAI 兼容协议，`api_endpoint` 指向本地即可，几乎零改动；
     - 量化（INT4/INT8）与推理加速（TensorRT / CUDA），论证显存与延迟；
     - 运行前通过 `bind_tools` 校验模型的工具调用能力，不支持工具调用的模型立即失败，避免执行中途报错（`app/agents/graph/__init__.py`）。
  3. **Agent 编排与自主决策**：LangGraph 状态机、审批中断（`approval_interrupt`）、风险分级（`risk_check`）、工具路由（`tool_router`）、检查点恢复；会话租约互斥（`agent_service/lease.py`）防止同一会话并发运行串写 checkpoint / 审批状态；待审批过期与主动取消（`agent_service/pending.py`）；审批恢复沿用发起时的原模型记录 ID；首次运行与审批恢复复用同一 SSE 事件转换器（`events/stream_tracker.py`），前端展示一致。
  4. **会话树形存储**：三类数据（Entry / Record / Fact）、append-only、不变式校验、崩溃恢复、fork / lane。
  5. **上下文压缩**：触发判定、切割点、双路径 token 估算、迭代式摘要、文件跟踪、与 Agent 闭环；**结合 1B 模型短上下文论证必要性**。
  6. **工具系统**：只读 / 写工具分离，工具结果视为不可信数据。
  7. **安全设计**：API Key 加密（本地部署可简化但保留）、JWT、多家庭隔离、限流预算、写操作完整审计链（调用参数 / 审批决定 / 执行结果 / 错误码，按 `run_id` 串联）、敏感信息脱敏、高风险审批不可绕行。
  8. **预期技术指标**：指令解析准确率、写操作误执行率（0）、**边缘推理延迟 / 生成速度 / 显存占用（实测填值）**、上下文窗口（MiniCPM 1B 实际值）、长对话维持、离线可用、并发。
