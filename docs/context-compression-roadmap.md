# 上下文压缩技术路线图

> 适用项目：智能家居 Agent 上下文压缩引擎
> 目标：在有限上下文窗口下，保障长会话连续性、工具调用可追溯性、分支切换无损性，并避免重复 / 无效压缩。

## 二、模块详解

### 3.2.1.2 三源触发 + 五重防御跳过

```mermaid
graph LR
    subgraph SRC[触发源]
        S1[阈值触发<br/>每轮后估算 token]
        S2[溢出触发<br/>模型长度截断]
        S3[手动触发<br/>用户/compact]
    end

    subgraph DEF[五重防御跳过]
        D1[1. 压缩未启用]
        D2[2. 已压缩过]
        D3[3. 消息被中止]
        D4[4. 无内容]
        D5[5. 上次用量早于压缩边界]
    end

    OUT[进入压缩流程]

    S1 --> G{五重防御}
    S2 --> G
    S3 --> G
    G -->|命中任一规则| SKIP[跳过压缩]
    G -->|全部通过| OUT
    D1 -.规则.-> G
    D2 -.规则.-> G
    D3 -.规则.-> G
    D4 -.规则.-> G
    D5 -.规则.-> G
```

**触发源**

| 来源 | 触发条件 | 行为 |
| --- | --- | --- |
| 阈值触发 | 每轮推理后自动估算 token，达 `窗口 - 预留` | 后台评估，进入压缩 |
| 溢出触发 | 模型返回长度截断 | 调用方触发并自动重试一次 |
| 手动触发 | 用户输入 / 显式 `compact` 命令 | 立即执行压缩 |

**五重防御跳过规则**

1. **压缩未启用**：全局开关关闭时直接跳过
2. **已压缩过**：本轮已触发过压缩，避免重复
3. **消息被中止**：上游消息处于中止态，跳过
4. **无内容**：无可压缩消息，跳过
5. **上次用量早于压缩边界**：token 计量基准失效，跳过

> 核心目的：杜绝重复压缩与无效压缩，保证每次压缩都是"有意义的一次"。

### 3.2.1.3 双路径 Token 估算容错

```mermaid
graph TD
    A[读取历史用量字段] --> B{是否有<br/>最后一个正常助手消息?}
    B -->|是| P1[路径1<br/>基于真实 usage 精确计算]
    B -->|否| P2
    A --> C{所有用量<br/>均缺失或异常?}
    C -->|是| P2[路径2<br/>字符数/4 启发式估算]
    C -->|否| P1
    P1 --> D[按角色加权求和]
    P2 --> E[按角色类型估算]
    D --> F[输出 token 用量]
    E --> F
```

**两条路径**

- **路径 1：真实用量**：基于最后一个正常助手消息返回的 usage 字段，向前回溯累加历史上下文 token。
- **路径 2：启发式估算**：所有 usage 缺失或异常时启用，按角色类型以 `字符数 / 4` 估算。

**双路径自动择优**

- 优先路径 1（精度高）
- 路径 1 失效时无缝切换到路径 2
- 即使本地 1B 量化模型偶发返回异常，也能继续推进压缩流程，避免单路径方案导致的"压缩卡死"。

### 3.2.1.4 语义安全切割点算法

```mermaid
graph TD
    A[从最新条目开始] --> B[向最早方向累积 token]
    B --> C{达保留尾巴阈值?}
    C -->|否| B
    C -->|是| D[回退定位首个合法切点]
    D --> E{切点类型}
    E -->|用户| S1[splitturn: 注入用户前缀]
    E -->|助手| S2[splitturn: 注入助手前缀]
    E -->|命令执行| S3[splitturn: 注入命令前缀]
    E -->|自定义| S4[splitturn: 注入自定义前缀]
    E -->|分支摘要| S5[splitturn: 注入分支摘要]
    E -->|压缩摘要| S6[splitturn: 注入压缩摘要]
    E -->|工具结果| X[❌ 不可作为切点]
```

**核心不变量**

> "工具结果"永远不可作为切割点 —— 防止上下文断裂

**六类合法切点**

1. 用户
2. 助手
3. 命令执行
4. 自定义
5. 分支摘要
6. 压缩摘要

**算法流程**

1. 从最新条目向最早方向累积 token
2. 达到"保留尾巴"阈值后回退
3. 定位首个合法切点
4. 根据切点类型动态构建 `splitturn` 结构
5. 确保历史尾部与当前轮次前缀完整衔接

### 3.2.1.5 迭代式更新摘要 + 虚拟条目映射

```mermaid
graph LR
    subgraph A[传统模式 ❌]
        A1[每次从零总结] --> A2[信息丢失严重]
    end

    subgraph B[本项目 ✅]
        B1[读取旧摘要] --> B2[保留未覆盖信息]
        B2 --> B3[迁移已完成项]
        B3 --> B4[更新下一步状态]
        B4 --> B5[精确保留实体: 路径/错误]
        B5 --> B6[新摘要]
    end

    subgraph C[虚拟条目]
        C1[上次保留尾巴] --> C2[映射为虚拟消息]
        C2 --> C3[纳入下次切割计算]
    end

    B6 --> C3
```

**更新式提示词（取代"从零总结"）**

- 保留旧摘要中未被新历史覆盖的信息
- 迁移已完成项
- 更新下一步状态
- 精确保留文件路径、错误消息等关键实体

**虚拟条目映射**

- 将上次压缩的"保留尾巴"重新映射为虚拟消息条目
- 纳入下次切割计算
- 使压缩后的消息仍被视为有效历史

> 效果：连续压缩 5–10 次后仍保持高精度。

### 3.2.1.6 分支导航自动归并摘要

```mermaid
graph TD
    A[用户 /tree 切换分支] --> B[旧分支被抛弃]
    B --> C[压缩为分支摘要节点]
    C --> D[逆向+正向遍历]
    D --> E[定位公共祖先分叉点]
    E --> F[按 token 预算挑选]
    F --> G{优先级}
    G -->|最高| P1[保留已有压缩摘要]
    G -->|次高| P2[保留分支摘要节点]
    G -->|其后| P3[普通条目]
    P1 --> H[注入目标分支]
    P2 --> H
    P3 --> H
```

**算法步骤**

1. 逆向 + 正向遍历定位公共祖先分叉点
2. 按 token 预算从最新条目往回挑选
3. 优先保留**已有的压缩摘要**与**分支摘要**节点

> 目的：历史压缩成果在分支切换中不丢失。

### 3.2.1.7 跨压缩文件操作累积跟踪

```mermaid
graph LR
    A[助手消息] --> B[工具调用块]
    B --> C{操作类型}
    C -->|读| R[读取文件集合]
    C -->|写| W[修改文件集合]
    C -->|编辑| E[编辑文件集合]
    R --> D[去重]
    W --> D
    E --> D
    D --> F[从上次压缩继承 + 本次新增]
    F --> G[XML 块注入摘要 details]
```

**三集合累积**

- **读取文件集合**：从 `read` 类工具调用提取
- **修改文件集合**：从 `write` 类工具调用提取
- **编辑文件集合**：从 `edit` 类工具调用提取

**累积与去重**

- 从上次压缩继承并叠加本次新增
- 跨多次压缩持续累积
- 最终以 XML 块形式注入摘要 `details` 字段

> 价值：智能家居 Agent 对文件 / 函数 / 路径操作强依赖，仅凭摘要即可获知完整操作历史。

### 3.2.1.8 路由隔离 + 协作式取消

```mermaid
graph TD
    A[摘要请求] --> B[分配全新隔离 ID]
    B --> C[独立路由, 不污染主对话]
    C --> D{用户是否中断?}
    D -->|否| E[完成摘要]
    D -->|是| X[协作式取消]
    X --> Y[下次摘要请求前<br/>立即抛异常]
    Y --> Z[不留半成品节点]
    E --> F[写回会话树]
```

**路由隔离**

- 每次摘要请求分配全新隔离 ID
- 防止大提示词污染主对话路由
- 与主对话的消息流解耦

**协作式取消**

- 用户主动中断压缩时立即终止
- 下次摘要请求前立即抛出异常
- 不留半成品节点
- 保障系统状态一致性

### 3.2.1.9 摘要真正回注 Agent 上下文

```mermaid
graph TD
    A[每轮推理结束] --> B[异步触发压缩<br/>独立线程]
    B --> C{压缩完成?}
    C -->|否| W[等待]
    C -->|是| D[下次 Agent 运行前]
    D --> E[清空 LangGraph 检查点旧历史]
    E --> F[从会话树重建上下文]
    F --> G[压缩摘要以<br/>带标签的人类消息注入]
    G --> H{类型判断}
    H -->|压缩摘要| I1[注入, 标签 CompactionSummary]
    H -->|工具结果| I2[跳过]
    H -->|命令执行| I3[跳过]
    I1 --> J[进入模型输入]
```

**关键设计**

- **异步触发**：每轮推理结束后异步触发压缩，独立线程，不阻塞事件循环
- **检查点重置**：压缩完成后，下次 Agent 运行前清空 LangGraph 检查点旧历史
- **上下文重建**：从会话树重建上下文
- **带标签注入**：压缩摘要以带标签的人类消息形式注入，例：
  ```
  [CompactionSummary] ...历史摘要内容...
  ```
- **明确标识**：标识其为历史摘要而非新指令
- **中间态跳过**：工具结果、命令执行等中间状态不进入对话历史

> 突破"只存不喂"的行业惯例，实现压缩与 Agent 上下文的真正接通。
